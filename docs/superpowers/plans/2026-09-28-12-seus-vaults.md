# "Seus vaults" e sincronização automática — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a seção Sincronização vira a lista "Seus vaults" (cada vault uma vez, com caminho e
estado), a chave de envelope passa a nascer no login e pertencer a uma conta, e todo vault
sincronizado deste computador sincroniza sozinho enquanto o app está aberto.

**Architecture:** três camadas independentes: (1) conta — `entrar`/`criar` devolvem a chave de
envelope junto da sessão, e o cofre guarda chave + e-mail; (2) coordenação — o Rust expõe quais
vaults estão abertos e uma trava por vault, usada tanto pela janela do vault quanto pelo
sincronizador em segundo plano; (3) tela — um modelo puro monta a lista a partir de três fontes, e
a seção só desenha e dispara ações.

**Tech Stack:** Rust (Tauri 2), TypeScript, React 19, zustand, vitest (node, sem jsdom).

**Spec:** `docs/superpowers/specs/2026-09-27-seus-vaults-design.md` (aprovado). Contexto:
`docs/17-sincronizacao.md`, `docs/18-servidor.md`, ADR-33/39/40.

## Global Constraints

- Português do Brasil em nomes e comentários. Todo texto de interface pelo catálogo
  (`src/i18n/catalogo/sync.ts`), pt-BR e inglês, sentence case, sem emoji; `cobertura.test.ts` passa.
- Nenhum valor visual fora dos tokens de `globals.css` / `docs/06-design-system.md`; componentes
  existentes (`Botao`, `BotaoIcone`, `Campo`, `Dialog`, as linhas `LinhaConfig` das Configurações).
- Hooks antes de qualquer `return`. `Dialog` por portal.
- Testes só de módulos puros ou stores/serviços com dependências injetadas — sem jsdom, sem
  `.test.tsx`. Teste antes, visto falhando. **Lição de 23/09:** testar o efeito visível; revisar
  todos os caminhos de chegada (engrenagem, Ctrl+,, ícone do rodapé, "Entrar na conta" do
  assistente, Configurações já abertas).
- A senha nunca é persistida nem logada. A chave de envelope só existe em memória e no cofre.
- **Nunca dois ciclos de sincronização no mesmo vault ao mesmo tempo** (spec §3).
- **Higiene de commit:** a árvore principal está limpa; mesmo assim, commit com pathspec
  (`git add -- <novos>`; `git commit -m "..." -- <caminhos>`), nunca `git add -A`, `git add .`,
  `git commit -a`; `index.lock`: espere e tente de novo. Não suba o app.

## Review Focus

1. **Troca de conta no mesmo computador** (entrar com a conta B depois da A, sem "sair"): a chave
   de A não pode ser usada para B — dono esperaria que B só veja e crie vaults com a chave de B.
   Teste na Task 2.
2. **Vault aberto numa janela enquanto o segundo plano o sincroniza**: nenhuma escrita dupla; a
   janela espera o ciclo do segundo plano terminar. Teste na Task 3 (trava) e Task 5 (pula aberto).
3. **Pasta do vault sincronizado apagada ou movida pelo Explorer**: o segundo plano não recria a
   pasta nem baixa tudo num lugar inesperado; a lista mostra "Pasta não encontrada". Teste na
   Task 4 (lista) e Task 5 (segundo plano pula pasta inexistente).
4. **Vault na nuvem cujo envelope não abre** (criado com outra senha): a lista não quebra nem
   some com os outros; mostra o estado próprio. Teste na Task 4.
5. **Baixar para uma pasta onde já existe uma pasta com o nome do vault**: numera
   (`Nome (2)`), nunca mistura com a existente. Teste na Task 6.

### Task 2: Chave de envelope pertence à conta (sonnet, medium)

**Files:** `src/conta/ServicoConta.ts`, `src/conta/tipos.ts`, `src/conta/ServicoContaHttp.ts` (+ teste),
`src/conta/ServicoContaFake.ts` (+ teste), `src/conta/ServicoContaFakeDev.ts` (+ teste),
`src/conta/cofreChaveDeEnvelope.ts` + `CofreChaveDeEnvelopeFake.ts` (+ teste),
`src/estado/contaStore.ts` (+ teste), `src/ui/excalisidian/SecaoSincronizacao.tsx` (só o ponto que
pede a senha e grava a chave), `src/sync/ligarAoVault.ts` e demais leitores de
`cofreChaveDeEnvelope.ler()` (procure todos).

**Interfaces:**
- Produces:
  - `interface ResultadoLogin { sessao: Sessao; chaveDeEnvelope: Uint8Array }` (em `tipos.ts`).
  - `ServicoConta.entrar(email, senha): Promise<ResultadoLogin>`; `criar(...)`: idem. `renovar` e
    `sair` inalterados.
  - `CofreChaveDeEnvelope.ler(emailDaSessao: string): Promise<Uint8Array | null>` — devolve a
    chave só se o e-mail guardado (normalizado) for igual ao `emailDaSessao` normalizado; se for
    diferente ou formato antigo (base64 puro, sem e-mail), APAGA a entrada e devolve `null`.
  - `CofreChaveDeEnvelope.gravar(email: string, chave: Uint8Array)`; `apagar()`.
  - Formato no cofre: JSON `{"v":1,"email":"<normalizado>","chave":"<base64>"}`.
  - `useContaStore.getState().chaveDeEnvelopeAtual(): Promise<Uint8Array | null>` — atalho que
    chama `cofreChaveDeEnvelope.ler(sessao.email)` (null sem sessão).

- [ ] `ServicoContaHttp`: a derivação que já produz a prova devolve também a `chaveDeEnvelope`
  (mesma chamada de `derivarDaSenha`, UMA derivação por login). Teste: `derivar` injetado é chamado
  uma vez por `entrar` e uma por `criar`; a chave devolvida é a do resultado da derivação.
- [ ] Fakes (`ServicoContaFake`, `ServicoContaFakeDev`): chave determinística e barata,
  `sha256("chave-fake|" + email normalizado + "|" + senha)` — nunca `derivarDaSenha` (lento).
- [ ] `contaStore.entrar/criar`: depois de a sessão chegar, `cofreChaveDeEnvelope.gravar(email,
  chave)` com a postura "nunca rejeita" (falha vira `console.warn`, login continua valendo).
  `sair` continua apagando.
- [ ] `SecaoSincronizacao`: o fluxo "pedir senha" só aparece quando `chaveDeEnvelopeAtual()` é
  `null` com sessão ativa; ao confirmar, usa `contaStore.entrar(email, senha)` (que agora grava a
  chave sozinho) — remova a derivação separada que a seção fazia. Todos os leitores de
  `cofreChaveDeEnvelope.ler()` passam a usar `chaveDeEnvelopeAtual()`.
- [ ] Testes (antes, vistos falhando): entrar grava chave com e-mail; entrar com conta B depois de

### Task 4: Estado visível e o modelo da lista (sonnet, medium)

**Files:** `src/sync/estadoSync.ts` (+ teste), `src/estado/syncStore.ts` (+ teste),
`src/sync/listaDeVaults.ts` (+ teste).

**Interfaces:**
- Consumes: `carregarEstadoSync(raiz)`, `listarRecentes()` (`src/vault/vaultsRecentes.ts`),
  `VaultSincronizado` (`src/sync/tiposServidor.ts`).
- Produces:
  - `EstadoSync` ganha campos OPCIONAIS `ultimoCicloEm?: string` (ISO) e
    `ultimoErro?: ErroCiclo | null` — mesma versão de formato (campos ausentes = nunca rodou).
  - `syncStore` grava esses dois campos no `EstadoSync` ao fim de cada ciclo.
  - `type EstadoItem = "sincronizado" | "so-local" | "so-nuvem" | "pasta-nao-encontrada" | "outra-senha"`.
  - `interface ItemVault { chave: string; nome: string; caminho: string | null; idNaNuvem: string | null; estado: EstadoItem; ultimoCicloEm: string | null; ultimoErro: ErroCiclo | null; conflitosPendentes: number }`.
  - `montarListaDeVaults(entrada: { recentes: { caminho: string; existe: boolean; estado: EstadoSync | null }[]; nuvem: ({ id: string; nome: string } | { id: string; nome: null })[] }): ItemVault[]`
    — `nome: null` na nuvem = envelope não abriu. Regras: local com `EstadoSync` cujo `idDoVault`
    está na nuvem → "sincronizado" (se a pasta existe) ou "pasta-nao-encontrada"; local com
    `EstadoSync` cujo id NÃO está na nuvem → "sincronizado" com `ultimoErro` preservado (a lista não
    conclui sozinha que foi apagado); local sem `EstadoSync` → "so-local" (pasta inexistente sem
    estado: não aparece); nuvem sem local → "so-nuvem", ou "outra-senha" se `nome` null. Ordenação:
    sincronizados, só local, só nuvem, os demais; por nome dentro de cada grupo.
- [ ] Testes (antes, vistos falhando): um por estado; a mesma pasta aparece uma vez só; vault de
  outra senha não impede os demais (Review Focus 4); pasta sumida (Review Focus 3); contagem de
  conflitos vem de `conflitosPendentes`.
- [ ] Commit: `feat(sync): estado visivel por vault e modelo da lista seus vaults`.
