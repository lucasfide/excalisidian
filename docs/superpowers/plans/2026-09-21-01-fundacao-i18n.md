# Fundação de i18n — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** dar ao Excalisidian um catálogo de textos traduzível com português do Brasil como
idioma-fonte e inglês como segundo idioma, mais a preferência que escolhe entre os dois.

**Architecture:** um catálogo plano de chaves (`"vault.erro.nomeVazio"`) com o texto em
pt-BR como fonte da verdade e um mapa parcial em inglês por cima. Um tradutor puro resolve
chave + parâmetros e cai no pt-BR quando falta tradução. Um hook fino lê o idioma do
`prefsStore` e devolve o tradutor. Nenhuma biblioteca: o produto tem dois idiomas e um
formato de interpolação, e um `Record` com teste cobre isso melhor que uma dependência.

**Tech Stack:** TypeScript, zustand, `@tauri-apps/plugin-store`, vitest.

**Spec:** `docs/superpowers/plans/2026-09-21-servicos-online-indice.md` (etapa 03 do
relatório "Excalisidian Premium").

## Global Constraints

- Português do Brasil em nomes de arquivo, componentes, variáveis e comentários.
- Interface em sentence case, sem emoji.
- Nenhum valor de cor, fonte, espaçamento, raio ou sombra fora dos tokens de
  `src/estilos/globals.css`. Nenhuma classe de cor padrão do Tailwind.
- Testes só de módulos puros — o projeto não tem jsdom e não existe nenhum `.test.tsx`.
- Teste roda com `npm test`. Arquivo `.test.ts` ao lado do módulo.
- Caminhos internos com `/` e `.normalize("NFC")`.

## Estrutura de arquivos

| Arquivo | Responsabilidade |
|---|---|
| `src/i18n/idioma.ts` | O tipo `Idioma`, a lista válida, o guardião de tipo e a detecção pelo idioma do sistema. Folha de dependências: não importa nada. |
| `src/i18n/catalogo.ts` | Os textos. `PT_BR` é a fonte da verdade e define o tipo `ChaveTexto`; `EN` é parcial por cima. |
| `src/i18n/tradutor.ts` | Resolução de chave, interpolação de parâmetros e queda para pt-BR. Puro. |
| `src/i18n/useTexto.ts` | Hook React de três linhas que liga o `prefsStore` ao tradutor. Sem lógica. |
| `src/estado/prefsStore.ts` | Ganha o campo `idioma`, a persistência e o `definirIdioma`. |
| `src/vault/mensagensErroVault.ts` | Primeira migração: vira mapa de código → `ChaveTexto`. |

A separação entre `catalogo.ts` (dados) e `tradutor.ts` (comportamento) é o que permite
testar a resolução sem depender do conteúdo dos textos, e crescer o catálogo para centenas
de chaves sem tocar na lógica.

// src/i18n/idioma.ts
// Os dois idiomas do produto. Folha de dependências: nada importa daqui pra cima.
// Português do Brasil é a fonte da verdade dos textos (ver catalogo.ts); inglês é a
// tradução. Não há terceiro idioma previsto — quando houver, entra aqui e em CATALOGOS.

export type Idioma = "pt-BR" | "en";

export const IDIOMAS: readonly Idioma[] = ["pt-BR", "en"];

export function ehIdioma(v: unknown): v is Idioma {
  return typeof v === "string" && (IDIOMAS as readonly string[]).includes(v);
}

/** Escolhe o idioma a partir das tags BCP-47 do sistema (`navigator.languages`).
 * Qualquer variante de português serve pt-BR; o resto do mundo recebe inglês. */
export function idiomaDoSistema(tags: readonly string[] = []): Idioma {
  for (const tag of tags) {
    if (/^pt\b/i.test(tag)) return "pt-BR";
    if (/^en\b/i.test(tag)) return "en";
  }
  return "en";
}
```

// src/i18n/tradutor.ts
// Resolução de texto: chave → idioma pedido → português → a própria chave.
//
// A queda para o português é deliberada: uma tradução faltando mostra o texto certo em
// português, o que é feio mas legível. Mostrar a chave crua na tela seria pior. A chave só
// aparece quando ela não existe em lugar nenhum, e aí é bug de quem escreveu o JSX.

import type { Idioma } from "./idioma";

export type Tradutor = (chave: string, params?: Record<string, string | number>) => string;

const MARCADOR = /\{(\w+)\}/g;

/** Troca `{nome}` pelos parâmetros. Marcador sem parâmetro fica literal de propósito. */
export function interpolar(texto: string, params?: Record<string, string | number>): string {
  if (!params) return texto;
  return texto.replace(MARCADOR, (literal, nome: string) =>
    nome in params ? String(params[nome]) : literal,
  );
}

export function criarTradutorDe(
  catalogos: Record<Idioma, Record<string, string>>,
  idioma: Idioma,
): Tradutor {
  const escolhido = catalogos[idioma] ?? {};
  const fonte = catalogos["pt-BR"] ?? {};
  return (chave, params) => {
    const texto = escolhido[chave] ?? fonte[chave] ?? chave;
    return interpolar(texto, params);
  };
}
```

// PT_BR é a FONTE DA VERDADE e define o tipo ChaveTexto — uma chave só existe se estiver

// Regras de redação valem para os dois idiomas: sentence case, sem emoji, sem ponto final
// em rótulo de botão. O teste deste módulo cobre as invariantes, não a redação.

  // Criação de vault — doc 12 §2 / doc 04 §13.
  "vault.erro.nomeVazio": "Dê um nome ao vault.",
  "vault.erro.nomeInvalido":
    'O nome não pode ter / \\ : * ? " < > | nem começar com ponto.',
  "vault.erro.existe": "Já existe uma pasta com esse nome nesse local.",
  "vault.erro.paiIndisponivel": "Não foi possível acessar o local escolhido.",

  // Preferências.
  "prefs.idioma.rotulo": "Idioma",
  "prefs.idioma.descricao": "Muda o idioma da interface. Suas notas não são afetadas.",
  "prefs.idioma.ptBR": "Português do Brasil",
  "prefs.idioma.en": "English",
} as const;

export type ChaveTexto = keyof typeof PT_BR;

export const EN: Partial<Record<ChaveTexto, string>> = {
  "vault.erro.nomeVazio": "Give the vault a name.",
  "vault.erro.nomeInvalido":
    'The name cannot contain / \\ : * ? " < > | or start with a dot.',
  "vault.erro.existe": "A folder with this name already exists here.",

  "prefs.idioma.ptBR": "Português do Brasil",
  "prefs.idioma.en": "English",
};

  "pt-BR": PT_BR,

// src/i18n/useTexto.ts
// Liga o idioma do prefsStore ao tradutor. Três linhas de propósito: toda a lógica mora em
// tradutor.ts, que é puro e testado. O useMemo evita recriar o tradutor a cada render.

import { useMemo } from "react";

import { usePrefsStore } from "../estado/prefsStore";
import { criarTradutor } from "./catalogo";
import type { Tradutor } from "./tradutor";

export function useTexto(): Tradutor {
  const idioma = usePrefsStore((s) => s.idioma);

// src/vault/mensagensErroVault.ts
// Erros de `criarVault` (doc 12 §2 / doc 04 §13), pelo código que o Rust devolve em
// `Error.message`. Desde a fundação de i18n este módulo devolve CHAVE, não texto: quem tem
// o tradutor é o componente. Compartilhado por `DialogoCriarVault` e `TelaBoasVindas`.

import type { ChaveTexto } from "../i18n/catalogo";

const POR_CODIGO: Record<string, ChaveTexto> = {
  nome_vazio: "vault.erro.nomeVazio",
  nome_invalido: "vault.erro.nomeInvalido",
  existe: "vault.erro.existe",
  pai_indisponivel: "vault.erro.paiIndisponivel",
};

/** Código desconhecido cai em "não foi possível acessar o local": é verdade em qualquer
 * falha inesperada de criação, e é melhor que mostrar o código cru na tela. */
export function chaveDoErroVault(codigo: string): ChaveTexto {
  return POR_CODIGO[codigo] ?? "vault.erro.paiIndisponivel";
}
